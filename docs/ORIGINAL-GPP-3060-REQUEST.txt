==================================================
CONNECTION PROCESS
==================================================

When Connect is pressed:

1. Open the selected COM port.
2. Use 115200 / 8N1 / no handshake.
3. Send:

*IDN?

4. Parse the response.
5. Verify that the device is a GW Instek GPP-3060.
6. Extract model, serial number and firmware if possible.
7. Read current channel settings.
8. Read current output state.
9. Start live polling.

If there is no response:

Display a clear non-crashing error such as:

Device did not respond.

If another device answers:

Display something like:

Connected device is not a GW Instek GPP-3060.

IMPORTANT SAFETY RULE:

CONNECT MUST NOT MODIFY OUTPUT STATE.

If CH1 is already ON before connecting, the application must only read that state.

Do not turn it ON or OFF automatically.

==================================================
IMPORTANT TIMING WARNING
==================================================

GW Instek GPP-3060 native Sequence mode does NOT provide millisecond timing resolution.

Therefore do NOT falsely claim that a requested 50 ms or 100 ms transition is hardware-deterministic.

For millisecond Custom operations, clearly label execution as:

PC Timed

Add a warning such as:

PC-timed execution is not deterministic.
Actual transition timing may differ from the requested duration due to Windows scheduling, USB/serial communication and instrument response time.

Provide an architecture that can distinguish:

PC Timed

and:

GPP Native Sequence

For slower tests that can use the power supply's own native Sequence engine, the application should be able to support that later.

==================================================
SAFETY REQUIREMENTS
==================================================

These requirements are extremely important.

1. Application startup must NEVER automatically turn outputs ON.

2. Application startup should not arbitrarily turn outputs OFF either.

3. Connect must not change output state.

4. Disconnect must not change output state by default.

5. Voltage/current editing must not immediately affect hardware until Apply is pressed.

6. Output ON must always be a separate explicit user command.

7. ALL OUTPUT OFF must always be easy to access.

8. Invalid numeric values must be rejected before sending them to hardware.

9. Device disconnect should not crash the application.

10. Serial exceptions should appear as understandable UI errors.
